# Agent Trace (desktop)

The claude-trace-rs dashboard as a native app, built with Tauri 2. User-facing
documentation is in the [main README](../README.md#desktop-app); these are
notes for working on it.

## Layout

```
src/main.rs           window, plugins, start-up (attach or embed), IPC grant
src/backend.rs        embedded tracer / attach mode, live event feed
src/notify.rs         notification loop and tray status refresh
src/activity.rs       turn/idle/budget detection (pure, unit tested)
src/tray.rs           tray icon and menu
src/commands.rs       commands the dashboard calls
src/command_names.rs  the command list, shared with build.rs
src/settings.rs       settings.json
ui/index.html         start-up page shown until the dashboard is ready
capabilities/         permissions for the bundled start-up page
```

## How the window talks to Rust

The window loads the dashboard from the embedded server
(`http://127.0.0.1:<port>/`). Tauri treats that as a remote origin, so at
start-up `grant_dashboard_ipc` adds a capability for exactly that origin with
the `allow-<command>` permission of each command in `command_names.rs`
(generated by `build.rs`). Nothing else, including plugin commands, is
reachable from the page. The dashboard detects the app through
`window.__TAURI_INTERNALS__` and shows its desktop-only controls.

To add a command: write it in `commands.rs`, register it in
`generate_handler!` in `main.rs`, and add its name to `command_names.rs`.

## Running and testing

```bash
cargo run -p agent-trace-desktop
cargo test -p agent-trace-desktop
cd desktop && npx @tauri-apps/cli@2 build          # installers
```

Debug builds evaluate the JavaScript in `AGENT_TRACE_DEV_EVAL` once the
dashboard has loaded, which makes it possible to drive the IPC bridge end to
end without a WebDriver, for example under Xvfb on Linux:

```bash
AGENT_TRACE_DEV_EVAL="__TAURI_INTERNALS__.invoke('desktop_info').then(i => console.log(i))" \
  xvfb-run cargo run -p agent-trace-desktop
```

Release builds ignore the variable.
